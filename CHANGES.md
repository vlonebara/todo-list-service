# Отчёт об изменениях в dev

## Краткий итог

Сохранена архитектура handlers → service → db и независимые модели. Исправлены подтверждённые ошибки формы, поиска, HTTP-ответов и конкурентного завершения. Добавлены история с отменой, страницы, фильтры, экспорт, напоминания в открытой вкладке и резервные копии. Защита запросов и проверки стали общими и повторно используемыми.

Фронтенд использует обычные JavaScript-модули и fetch. Для запуска не нужен отдельный этап сборки интерфейса. Настройки и команды описаны в [README](./README.md).

## Как это работает простыми словами

1. Обработчик читает запрос и передаёт данные сервису.
2. Сервис проверяет поля и вычисляет календарные правила.
3. Хранилище выполняет SQL через общий пул соединений.
4. При изменении задачи хранилище сохраняет её прежнее и новое состояние вместе с изменением.
5. Отмена сравнивает текущее состояние с сохранённым и восстанавливает предыдущие данные.
6. Интерфейс показывает результат, разблокирует кнопку и обновляет список.

## История коммитов

### [08e8cb3](https://github.com/vlonebara/todo-list-service/commit/08e8cb3) — fixed task error responses

**Единая обработка ошибок задач.** Общий обработчик выбирает 400 для неверных данных, 404 для отсутствующей задачи и 500 для внутренних ошибок. Подробности БД остаются в логе.

**Зачем:** Убрано разное поведение GET, DELETE, POST и PUT; клиент получает предсказуемый результат.

**Проверки:** Проверка JSON-ответов и скрытия внутренних подробностей; интеграционные тесты.

### [1b8b4ef](https://github.com/vlonebara/todo-list-service/commit/1b8b4ef) — added request context to task storage

**Отмена запросов доходит до SQLite.** Контекст передаётся из HTTP-обработчиков через сервисы в ExecContext, QueryContext и QueryRowContext.

**Зачем:** Отключившийся клиент не должен оставлять ненужное ожидание соединения или запрос к БД.

**Проверки:** Отменённая запись не изменяет БД; интеграционные тесты.

### [42ad829](https://github.com/vlonebara/todo-list-service/commit/42ad829) — fixed next date calculation and date limits

**Расчёт повторений и границы календаря.** Дневной интервал вычисляется без перебора всех прошедших дней. Сравниваются календарные даты. Выход за 9999 год возвращает ошибку.

**Зачем:** Исправлена девятизначная дата и уменьшен объём вычислений для давних задач.

**Проверки:** Давние даты, високосные годы, будущая исходная дата и выход за диапазон; исходные тесты повторений.

### [6931797](https://github.com/vlonebara/todo-list-service/commit/6931797) — added request limits and secure auth cookies

**Защита HTTP и входа.** Добавлены таймауты, лимит JSON, ограничения длины полей и попыток входа, CSRF-защита Go. Сервер устанавливает HttpOnly-cookie. Без пароля разрешён только локальный адрес.

**Зачем:** Защита сосредоточена в общих функциях и проверяется до выполнения операций.

**Проверки:** Неверный Content-Type, большой и некорректный JSON, межсайтовый запрос, ограничения входа, атрибуты cookie и настройки запуска.

### [0db0d93](https://github.com/vlonebara/todo-list-service/commit/0db0d93) — added task history and undo. fixed concurrent completion

**История, отмена и согласованное завершение.** Версии схемы хранятся в PRAGMA user_version. Добавлена таблица истории со снимками до и после действия. Запись задачи и истории выполняется одной транзакцией. Завершение проверяет исходный снимок.

**Зачем:** История позволяет восстановить данные, а два запроса со старым состоянием не перезаписывают друг друга незаметно.

**Проверки:** Обновление старой БД, последовательная отмена, откат при ошибке истории, одновременное завершение; проверки с -race.

### [30aef02](https://github.com/vlonebara/todo-list-service/commit/30aef02) — fixed test isolation. added API status checks

**Безопасный самостоятельный запуск тестов.** TestMain создаёт временную БД и httptest-сервер, получает свежий JWT. Фиксированный токен убран. Добавлены проверки HTTP-кодов.

**Зачем:** Обычный go test больше не требует вручную запускать сервер и не очищает рабочую БД.

**Проверки:** Исходные сценарии проходят с включённой аутентификацией; отдельно проверяются 400, 401, 404 и 405.

### [180b672](https://github.com/vlonebara/todo-list-service/commit/180b672) — added task pages, filters and export

**Поиск, страницы, экспорт и готовность сервера.** Добавлены page и period, русский поиск без учёта регистра, полный JSON-экспорт и /api/health. Размер страницы остаётся 15.

**Зачем:** Можно получить все задачи, выделить нужный срок и сохранить данные.

**Проверки:** Две страницы, календарные границы, кириллица, специальные символы и полный экспорт.

### [a220b34](https://github.com/vlonebara/todo-list-service/commit/a220b34) — added database backup and restore

**Резервное копирование и восстановление.** Команды -backup и -restore используют согласованную копию SQLite, проверку целостности и отказ от перезаписи существующего файла.

**Зачем:** Копия содержит задачи, историю и версию схемы; восстановление сначала проверяется отдельно от рабочей БД.

**Проверки:** Восстановлены задача и история, проверены права копии 0600, отказ на существующем файле и неверной копии.

### [da20f96](https://github.com/vlonebara/todo-list-service/commit/da20f96) — updated frontend. added history and reminders

**Читаемый интерфейс на обычном JavaScript.** Созданы небольшие модули API, формы, списка, истории и напоминаний. Состояние формы сбрасывается полностью, кнопки блокируются на время запросов, ошибки API показываются текстом. Добавлены страницы, фильтры, отмена, экспорт и выход.

**Зачем:** Фронтенд можно читать и менять без сборщика. Ошибки формы и поиска исправлены в месте их возникновения.

**Проверки:** В браузере проверены вход и выход, изоляция правил повторения, новая форма, поиск C++/A&B/#tag, кириллица, страницы, история, отмена, двойная отправка и напоминание во вкладке. Узкая раскладка проверена на ширине 375 px.

### [ca1d8c1](https://github.com/vlonebara/todo-list-service/commit/ca1d8c1) — fixed edge cases and simplified validation

**Повторная проверка и упрощение общих правил.** Добавлена общая ParseDate. Неизвестное удаление при отмене возвращает 409. Тестовые помощники используют только собственные настройки. В локальном режиме проверяется Host. Расширены проверки JWT; сохранены показ пароля и сброс поиска.

**Зачем:** Повторяющаяся проверка даты имеет один источник. Дополнительные граничные сценарии не смешиваются с обычным отсутствием задачи.

**Проверки:** Сначала воспроизведён неверный код отмены, затем тест прошёл. Проверены срок и алгоритм JWT, парольная метка, локальные Host и новые API истории/экспорта.

### [11f14ae](https://github.com/vlonebara/todo-list-service/commit/11f14ae) — updated Go and Docker. added CI checks

**Обновление Go и проверка контейнера.** Минимальная версия обновлена до Go 1.26.11. Новые файлы БД создаются с правами 0600; добавлено короткое ожидание блокировки SQLite. Контейнер работает от UID 10001. CI проверяет код, запуск образа и известные уязвимости.

**Зачем:** Устранены найденные сканером проблемы старого Go; будущие изменения получают автоматическую проверку.

**Проверки:** Локально проходят go vet, тесты с -race и govulncheck. Docker daemon на компьютере недоступен; контейнерная проверка выполнена в GitHub Actions.

## Итоговые проверки

- Приложение собирается с Go 1.26.11.
- После законченных блоков сервер запускался заново с отдельной временной БД и выполнялся `go test ./tests -v`.
- `go test -race ./... -count=1` проходит.
- `go vet ./...` проходит.
- `govulncheck ./...` возвращает `No vulnerabilities found`.
- Запрос экспорта проверен через HTTP API; получение события скачивания встроенным браузером не подтверждено.
- Рабочая БД для проверок не использовалась.
- [GitHub Actions для кода 11f14ae](https://github.com/vlonebara/todo-list-service/actions/runs/42986825983): задачи `go` и `container` завершились успешно, включая сборку, запуск, готовность, UID и сканирование образа.

Последний коммит документации `updated README and changes report` содержит инструкции и этот отчёт.

## Что требует согласования

По правилу владельца об удалении файлов пока ожидаются два решения:

- удалить неиспользуемые старые `web/js/axios.min.js`, `web/js/scripts.min.js`, `web/css/theme.css` и `web/css/style.css`;
- исключить `scheduler.db` из отслеживания Git, сохранив локальный файл.

Ранее записанная БД останется в истории Git. Её содержимое в этой работе не исследовалось.

## Условия эксплуатации

- Для внешнего адреса нужен пароль и HTTPS-прокси.
- Выход очищает cookie браузера; принудительный сброс всех JWT выполняется сменой ключа и перезапуском.
- Напоминания работают только при открытой странице.
- История не очищается автоматически.
- Восстановление создаёт новый файл и не перезаписывает рабочую БД.
